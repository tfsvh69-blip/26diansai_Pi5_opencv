## 2026-07-17　摄像头去畸变画面 开机自启动

**目的**：接上显示器后，树莓派一上电（自动登录进桌面）就自动运行 C++ 去畸变预览窗口
`cpp_code/undistort_view`，无需任何手动操作、无需输密码。

**采用方案**：桌面 autostart（**不是**系统级 systemd service）。
因为程序要弹 `cv2.imshow`/highgui 窗口，系统级服务跑在无图形环境的后台会失败；
autostart 跟随已登录的桌面会话启动，自动继承 `DISPLAY`。

**利用到的本机现状（未改动，只是依赖）**：
- gdm3 已开启自动登录：`/etc/gdm3/custom.conf` → `AutomaticLoginEnable=true`、`AutomaticLogin=hao`
  （开机自动进桌面，不输密码）。
- 桌面是 Xorg/X11 会话：`/etc/gdm3/custom.conf` → `WaylandEnable=false`，`DISPLAY=:0`。
- `/dev/video0` 靠 systemd-logind 的 uaccess **动态 ACL**（`user:hao:rw-`）授权：
  `hao` **不在 video 组**，但本地图形会话登录后自动获得读写权限；autostart 在登录之后触发，权限一定就位。

**新增/改动的文件**：
| 文件 | 说明 |
|---|---|
| `cpp_code/autostart_camera.sh`（新增，已 `chmod +x`） | 启动包装脚本：`cd` 到 cpp_code 目录（undistort_view 用相对路径读 `camera_calib.yaml`）→ 循环等 `/dev/video0` 就绪（最多 30s，防开机设备未枚举完）→ `sleep 2` 稳定 → `exec ./undistort_view`。日志写到 `~/.local/state/camera-autostart.log`（每次覆盖） |
| `~/.config/autostart/camera-undistort.desktop`（新增，用户目录，不在本仓库内） | 桌面自启动项，`Exec=` 指向上面的脚本，`X-GNOME-Autostart-Delay=3` 延迟 3s 等桌面就绪 |
| `/home/hao/Desktop/系统配置记录.md` | 全局系统记录里同步追加了本条 |

**验证**：`DISPLAY=:0 timeout 8 bash cpp_code/autostart_camera.sh` 实测通过——
摄像头 640x480 打开成功、载入标定 RMS=1.53792px、默认去畸变、窗口正常显示。

**回滚 / 关闭自启动**：删除或改名 `~/.config/autostart/camera-undistort.desktop` 即可，
其余文件删不删都不影响系统。

**已知局限**：autostart 只启动一次，程序崩溃或摄像头拔插不会自动重启。
如需「崩溃自动拉起」，改用 `systemctl --user` 服务（绑定 `graphical-session.target`）。

**触发时机**：不是「开机」动作本身触发，而是**每次进入 hao 的图形桌面会话时**由 GNOME
会话拉起一次（开机自动登录 → 进桌面 → 触发；注销重登、切换用户再切回也会触发；纯 SSH
无图形会话不触发；锁屏解锁不重新触发）。

**【当前状态：已暂时关闭 · 2026-07-17】** 已把 `~/.config/autostart/camera-undistort.desktop`
改名为 `camera-undistort.desktop.disabled`（autostart 只识别 `.desktop` 结尾，改名即被忽略）。
其余脚本/可执行文件均保留，仍可手动运行。
**重新开启**：`mv ~/.config/autostart/camera-undistort.desktop.disabled ~/.config/autostart/camera-undistort.desktop`

## 2026-07-24　新增 `code/opencv_code/` 纯 OpenCV 钢珠检测（替代 YOLO）

**目的**：YOLO NCNN 检测只有 ~17FPS，太慢。小钢珠（直径 1cm 金属镜面球）在固定桌面场景下不需要
通用目标检测，纯 OpenCV HoughCircles + 金属镜面确认即可达到 89FPS，相机 30FPS 满帧无压力。

**做了什么**：
1. 创建 `code/opencv_code/` 目录，含四个文件：
   - `ball_detector.py` — 检测核心：HoughCircles 收紧候选 → 金属镜面确认（高光+对比度）→ 打分
   - `v1.0.py` — 正式主程序：复用 task_code 的 camera_link/serial_link/protocol 框架
   - `tune_detector.py` — 中文滑条调参工具（PIL 渲染中文 + 视觉反馈：候选/淘汰原因/主目标）
   - `config.py` — 检测参数持久化到 detector_config.json
2. 安装 Pillow 12.3 到 vision_env venv（用于调参工具的中文渲染，OpenCV 不支持中文字符）：
   ```bash
   /home/hao/vision_env/bin/pip install Pillow
   ```
3. `.gitignore` 增加 `code/opencv_code/detector_config.json`

**核心算法**：HoughCircles (dp=1.2, minDist=20, param1=120, param2=30, minR=10, maxR=18)
→ 对每个候选打分：必须有镜面高光(Vmax≥205) + 内部对比度(Vstd≥18) → 选分最高为主目标。
关键：max_radius 从 22 收到 18 杀掉了背景 r≈21 的大假圆，离线命中率从 8/12 → 12/12。

**性能**：实时 149/150 命中，~11ms/帧(~89FPS)，x 抖动 1.7px，y 抖动 12.8px。

**验证**：已经 headless 跑过两轮 150 帧自测，导入链全部 OK。

**回滚**：直接跑 `task_code/v1.0.py` 即回到 YOLO 版本。opencv_code 不影响其他目录。

## 2026-07-25　opencv_code 检测算法从 v1 升级到 v2

**目的**：v1 检测极不稳定——HoughCircles 参数过严（param2=32）、打分硬否决（min_vstd=30.8 不达标直接 -1）、保持锁定只有 10 帧硬限（~333ms），导致频繁 found/lost 切换，串口不停发 0，"一直空血"。v2 要用**检测+跟踪融合**替代纯逐帧检测。

**改动文件**：

| 文件 | 改动说明 |
|------|---------|
| `code/opencv_code/ball_detector.py` | **完全重写**。核心变更见下方「v2 算法要点」 |
| `code/opencv_code/tune_detector.py` | 适配 v2，HUD 显示"信心=xx%"取代旧 `_hold_frames` 字段 |
| `code/opencv_code/v1.0.py` | 画面 HUD 增加 `CONF=xx%` 实时置信度显示 |
| `code/opencv_code/detector_config.json` | **重置为默认值**（清除了旧版参数：param2=32/min_vstd=30.8，改用 v2 内置默认值）。当前用户现场调参后的值见文件本身。 |

**v2 算法要点**（对比 v1）：

| 维度 | v1 | v2 |
|------|----|----|
| 打分机制 | 硬阈值否决（min_vmax、min_vstd 任一不达标→score=-1 直接淘汰） | 多因素综合评分：亮度(0~30) + 高光(0~30) + 对比度(0~20) + 空间一致性奖励(0~40)。单项弱可由其他项补救 |
| 丢帧行为 | 静止 hold 最后位置，10 帧（~333ms）硬限，超限突然丢锁 | **速度预测**：丢失期间按最近观察速度惯性前推（每帧速度 ×0.92 衰减），位置继续顺滑移动 |
| 锁定持久性 | 10 帧硬限，超限后 found 直接跳 0 | **置信度衰减**：检出一帧 +0.25，漏一帧 -0.025。满置信度可撑 ~40 帧（~1.3s），置信度从 100%→0% 逐步下降，串口期间持续发 found=1 |
| 抗噪声 | 检测到新位置直接跳过去 | 检测位置离预测位置近时空间一致性奖励 +40 分（平方衰减），大幅抑制误检跳变 |

**结论**：
> 后面还需要观察 **detect 函数 消耗的时间**、**整个调用流程的优化**、以及**接口是否完全适配**这三个方面，来决定要不要进一步调。

**参数持久化兼容**：`detector_config.json` 的 `detector` 字段已重置为空 `{}`（程序启动时用 `BallDetector()` 内置默认值）。`load_dict()` 只认 `TUNABLE` 内的 key，旧版残留字段（`temp_dist`、`temp_bonus`、`temp_min_vmax`、`temp_min_vstd`）加载时自动忽略，不会崩。

**回滚**：`git checkout` 恢复到旧版 `ball_detector.py` 即可。`detector_config.json` 如需回滚到旧版参数可通过 git 恢复。

## 2026-07-31　rollball.service —— `v1.1_beta.py` 开机自启动（同日从 headless 改为完整 GUI）

**目的**：树莓派一上电自动运行滚球视觉检测主程序，表现跟手动在终端跑 `python3 .../v1.1_beta.py` 一模一样——有主窗口、有 Tuning 滑条、有局域网推流。

**采用方案**：**用户级 systemd 服务**（`systemctl --user`，不是系统级 systemd service）。
因为需要完整 GUI（cv2.imshow 窗口 + Tuning 滑条），必须等桌面登录就绪后有 `DISPLAY=:0` 才能跑，系统级 `multi-user.target` 无图形环境。绑定 `graphical-session.target` + `ExecStartPre=/bin/sleep 8`（等桌面稳定），行为跟手动终端跑一模一样。
参照了本机已有的 `ruikang.service`（`~/.config/systemd/user/ruikang.service`）同款写法。

**版本演变**：
| 版本 | 服务位置 | 绑定目标 | 启动参数 | 有无窗口 | 状态 |
|------|---------|---------|---------|---------|------|
| v1（系统级 headless） | `/etc/systemd/system/rollball.service` | `multi-user.target` | `--headless` | 无 | 已停用并删除 |
| v2（用户级 GUI · 当前） | `~/.config/systemd/user/rollball.service` | `default.target`+`graphical-session.target` | 无 | 有（完整 GUI） | `enabled`，当前 inactive（手动停着） |

**新增/改动文件**：
| 文件 | 说明 |
|------|------|
| `~/.config/systemd/user/rollball.service`（新增） | 用户级服务单元。`After=graphical-session.target`（等桌面就绪）、`ExecStartPre=/bin/sleep 8`（再等桌面稳定）、**不带 `--headless`**（完整 GUI）、`Restart=always`+`RestartSec=5` |
| `/etc/systemd/system/rollball.service` | v1 系统级服务（已 `disable` + `rm`，同日清理） |
| `/home/hao/Desktop/系统配置记录.md` | 全局系统记录 rollball.service 章节已同步更新为 v2 用户级 |

**代码未改动**：`v1.1_beta.py` 一行没改。服务只是不加 `--headless` 参数而已。

**开机自启链**：上电 → gdm3 自动登录 hao → 用户 systemd 实例启动 → `graphical-session.target` 就绪 → `sleep 8`（桌面稳定）→ 脚本启动（跟手动跑一模一样）。

**关闭服务**（注意都带 `--user`，**不需要 sudo**）：
```bash
systemctl --user stop rollball.service           # 停止本次运行
systemctl --user disable rollball.service         # 取消开机自启（长期关闭）
```

**完全卸载**：
```bash
systemctl --user stop rollball.service
systemctl --user disable rollball.service
rm ~/.config/systemd/user/rollball.service
systemctl --user daemon-reload
```

**踩坑记录**：
- v1 安装后 crash-loop：8080 端口被手动终端进程占用 → 退出后正常。
- v2 同样 crash-loop：原因相同（用户正手动跑脚本调参占着 8080）。**以后手动跑脚本必须先 `systemctl --user stop rollball.service` 释放端口**，开机时没有这个问题。
- 用户级服务生命周期 = 桌面登录会话：注销桌面即停止，重新登录重新拉起。不同于系统级服务（开机到关机一直在）。
- ~~v1 的 SIGTERM 问题~~ v2 用户级服务不再有这个问题：用户级 systemd 发 SIGTERM 后会给进程一个 grace period 才 SIGKILL，且退出时 `KeyboardInterrupt` 等效于用户 Ctrl-C——但脚本的 `except KeyboardInterrupt` 只捕获 SIGINT 不捕获 SIGTERM，优雅退出清理仍不完美（不影响正常使用）。
