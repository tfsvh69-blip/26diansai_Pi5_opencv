# YOLO11n NCNN 三规格 树莓派5 性能测试记录

> 目的：把训练好的球检测模型（YOLO11n，单类 `ball`）三种输入规格 320/416/640
> 部署到本机树莓派 5，实测推理耗时与帧率，为现场选一个"速度/精度"较优的规格。

## 测试环境

| 项 | 值 |
|---|---|
| 设备 | Raspberry Pi 5 Model B（4 核 Cortex-A76 @ 2.4GHz，aarch64） |
| 日期 | 2026-07-24 |
| 推理框架 | ncnn（`pip install ncnn`，venv `/home/hao/vision_env`），4 线程 + fp16 |
| 模型 | Ultralytics YOLO11n → NCNN，单类 `ball`，`models/best_ncnn_{320,416,640}/` |
| 取帧负载 | 训练录像 `code/record_code/output/dataset_20260723_185257.mp4`（640×480，真实含多球场景） |
| 计时 | 每模型 200 帧，预热 15 帧；CPU 温度 47→56℃，全程 2400MHz 无降频 |

测量口径：`pre`=letterbox+归一化，`infer`=ncnn 前向，`post`=解码+NMS+反 letterbox，
`total`=三者之和（≈实时循环里一帧的检测耗时），FPS 由 total 均值换算。

## 实测结果

| 规格 | 纯推理 infer(ms) | 端到端 total(ms) | 检测 FPS | pre(ms) | post(ms) | 均检测数 |
|---|---|---|---|---|---|---|
| **320** | 52.2（p95 117.3） | 56.0 | **17.9** | 3.5 | 0.3 | 6.9 |
| 416 | 93.3（p95 161.3） | 99.8 | **10.0** | 6.2 | 0.4 | 7.0 |
| 640 | 200.7（p95 287.2） | 215.1 | **4.6** | 14.0 | 0.4 | 7.0 |

- **去畸变 remap 单帧约 3.6ms**。部署默认开去畸变，叠加后估算 FPS（未含摄像头读帧）：
  320 → 16.8、416 → 9.7、640 → 4.6。真实还要再加 USB/MJPG 读帧几毫秒。
- 三规格在这段素材上**平均检测数一致（~7）**、框位置吻合（同一帧不同规格框坐标基本重合，
  置信度均 0.9+），说明对"较大、较近的球"精度差别不大，主要差在速度。

### 现场实时实测（真实摄像头 + detect_live.py 窗口）

在接远程屏幕的桌面会话里跑 `detect_live.py`，读实时摄像头画面、开去畸变，
HUD 上观察到的端到端帧率（2026-07-24）：

| 规格 | 现场实时 FPS | 上面基准(录像回放) FPS |
|---|---|---|
| **320** | **~17** | 17.9 |
| 416 | **~12** | 10.0 |
| 640 | **~8** | 4.6 |

- 320 两种测法吻合；416/640 现场反而略高——基准取的是 200 帧均值、被少数 p95 慢帧
  拉高了 total，而实时 HUD 是滑动平均、更接近多数帧的稳态帧时。两者趋势一致，
  **现场实测更贴近实际使用体验**，选型以现场数据为准。

## 结论与选型建议

- **首选 320**：现场 ~17 FPS，实时性最好，对当前球目标精度已足够，是较优解。
- **备选 416**：现场 ~12 FPS。当出现更小/更远的球、320 漏检或框不准时再换，精度更高、帧率仍可接受。
- **不建议 640 做实时**：现场 ~8 FPS，延迟偏高；仅适合离线高精度分析或单帧标注核对。

> 现场经验法则：先用 320 跑，够用就锁定；发现小球/远球掉检再升 416；640 留作精度对照。

## 可选调优（未改动系统，供部署时参考）

- **CPU governor**：当前 `ondemand`，满载时能自动到 2400MHz，但推理间隔里会降频，
  导致每帧启动偶发变慢（表现为 p95 明显高于均值）。若要延迟更稳，可在部署时设
  `performance`（需 sudo，重启失效需做持久化），换取更一致的帧时。
- p95 高于均值主要是多任务调度抖动，非温度降频（全程 2400MHz、56℃，远未到 80℃阈值）。

## 脚本功能说明（`code/detect_code/`）

推理走原生 `ncnn`（`pip install ncnn`，轻量、不拖入 torch，反映真实部署帧率）。

| 脚本 | 功能 | 是否需摄像头/屏幕 |
|---|---|---|
| `yolo_ncnn.py` | YOLO11n NCNN 推理**封装**：letterbox 预处理 → ncnn 前向 → 解码+NMS → 把框还原回原图坐标。提供 `YoloNcnn` 类（`detect(frame)` 返回检测框与各阶段耗时）和 `draw_detections()`。被下面两个复用，不单独运行 | 否 |
| `detect_live.py` | **实时检测预览**：复用 `camera_common.py` 固定曝光/增益/白平衡打开摄像头，**默认去畸变**，画框并在 HUD 显示 规格/FPS/infer 耗时/检测数。运行时 `1/2/3` 切 320/416/640、`u` 切去畸变、`q` 退出 | 需（有 imshow 窗口） |
| `benchmark.py` | **三规格性能基准**：用训练录像帧回放做负载，逐模型测 pre/infer/post/total 各阶段耗时与 FPS，输出对比表；另测去畸变 remap 单帧开销 | 否（纯 SSH 可跑） |

关键实现点：
- **默认去畸变**——`detect_live.py` 有 `camera_calib.npz` 就默认喂去畸变画面，与 v1.2 /
  record_dataset 一致（部署与训练几何一致），符合项目约定。
- **模型输出**已实测为 `[5, N]`=`[cx,cy,w,h,置信度]`，框坐标已是输入尺度像素、已过 Sigmoid
  （DFL/anchor 解码烘焙进了计算图），后处理**不需手写 anchor 解码**。
- **踩坑**：`ncnn.Mat(numpy)` 只**包装**不拷贝缓冲区，预处理数组一出作用域就悬空、会段错误，
  已在 `yolo_ncnn.py` 里用 `.clone()` 让 Mat 拥有自有内存。

## 复现方法

