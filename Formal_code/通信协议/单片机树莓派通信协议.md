# 视觉端与单片机 UART0 通信协议

## 1. 串口参数

```text
UART0
115200 baud
8N1
无硬件流控
3.3V TTL
```

MCU 引脚：

```text
PA10 = TX
PA11 = RX
GND 共地
```

---

## 2. 通用帧格式

```text
$TYPE,DATA...*CHK\r\n
```

- `TYPE`：消息类型
- `CHK`：`$` 与 `*` 之间所有 ASCII 字节逐字节 XOR，使用两位大写十六进制表示
- `PING`、`PONG`、`TASK`、`ACK` 校验错误、字段错误或数据越界时直接丢弃
- `$X` 用于联调时，下位机必须先保留并在 OLED 显示原始数据字段，不能因格式、校验或范围问题把它隐藏；只有满足第 6 节正式格式和范围的 X 才能作为有效位置参与后续控制

---

## 3. 握手协议

### MCU → 视觉

```text
$PING,<id>*<CHK>\r\n
```

### 视觉 → MCU

```text
$PONG,<id>*<CHK>\r\n
```

说明：

- MCU 每次复位后只发送 3 次 `PING`，相邻两次间隔 500 ms；第 3 次后停止发送，直到下一次 MCU 复位
- 视觉程序完成相机、识别、显示和录像初始化后，才回复 `PONG`
- `PONG` 必须返回相同的 `id`
- 在任意一次 PING 后收到匹配 `PONG` 即判定视觉在线；最后一次匹配 `PONG` 后超过 3 s，OLED 显示视觉离线

---

## 4. 开始执行题目

### MCU → 视觉

```text
$TASK,<run_id>,<task_id>,START*<CHK>\r\n
```

示例：

```text
$TASK,8,3,START*<CHK>\r\n
```

字段：

- `run_id`：本次测试编号，每开始一次新测试加 1
- `task_id`：题号，范围 1～6
- 录像题号：`task_id=1～6` 都需要创建、写入和保存录像。其中题目 1 为 5 秒正常画面原始录像；题目 2～6 为题目过程录像
- 指定录像目录：视觉端使用配置项 `VIDEO_OUTPUT_DIR`，录像文件必须保存到该目录；目录不存在时应先创建

视觉端收到后：

1. 在 `VIDEO_OUTPUT_DIR` 创建录像文件
2. 文件名使用当前时间：

```text
YYYYMMDD_HHMMSS.mp4
```

3. 按题号写入画面：

   - `task_id=1`：逐帧写入正常相机画面，不得叠加 `TASK` 文字、检测框、坐标、时间戳或其他调试图层；该 MP4 用于检查原始画面链路
   - `task_id=2～6`：在录像画面左上角写入 `TASK <task_id>`

所有 `task_id` 均回复：

```text
$ACK,<run_id>,<task_id>,START*<CHK>\r\n
```

同一个 `run_id` 的重复 `START` 不得重复创建录像文件，只重复回复 ACK。

---

## 5. 结束执行题目

### MCU → 视觉

```text
$TASK,<run_id>,<task_id>,STOP*<CHK>\r\n
```

视觉端收到后：

所有 `task_id=1～6` 均应：

1. 停止并保存当前录像
2. 关闭视频文件

所有 `task_id` 均回复：

```text
$ACK,<run_id>,<task_id>,STOP*<CHK>\r\n
```

题目自动完成、用户退出题目或发生故障时，MCU 都应发送 `STOP`。题目 1 在启动后约 5 秒由 MCU 自动发送 `STOP`；用户提前退出时立即发送 `STOP` 并保存已录片段。

---

## 6. 相机水平像素位置

### 视觉 → MCU

```text
$X,<x_px>*<CHK>\r\n
```

示例：

```text
$X,0*<CHK>\r\n
$X,320*<CHK>\r\n
$X,640*<CHK>\r\n
```

定义：

- 单位：像素（px）
- 含义：相机图像中的水平 X 坐标
- 合法范围：`0 ～ 640`（含边界）
- 正式位置帧只接受无符号十进制整数；超出范围的帧不作为有效位置使用，但原始字段仍须显示在 OLED 以便排查链路

发送规则：

- 视觉端每读取并得到一条有效 X 像素坐标后，必须立即通过串口发送一帧 `$X,<x_px>`
- 不设置固定发送频率，不等待下一次定时发送，也不人为限速；实际发送频率随有效数据读取频率变化
- 只发送最新位置，不发送历史队列；若计算速度跟不上，也不得积压旧位置后补发
- 上位机应采用“读取有效数据 → 立即组帧 → 立即串口发送”的顺序，尽量降低从相机读取到 MCU OLED 显示的延迟

---

## 7. 丢球

视觉端无法可靠识别钢珠时发送：

```text
$X,NA*<CHK>\r\n
```

规则：

- 刚发生丢球时立即发送一次
- 持续丢球时每 200 ms 发送一次
- 恢复识别后立即恢复发送有效 `X`
- MCU 收到 `X,NA` 后立即停止使用上一帧位置
- 超过 100 ms 未收到新的有效 `X`，位置数据自动失效

---

## 8. 完整消息列表

### MCU → 视觉

```text
$PING,<id>*<CHK>\r\n
$TASK,<run_id>,<task_id>,START*<CHK>\r\n
$TASK,<run_id>,<task_id>,STOP*<CHK>\r\n
```

### 视觉 → MCU

```text
$PONG,<id>*<CHK>\r\n
$ACK,<run_id>,<task_id>,START*<CHK>\r\n
$ACK,<run_id>,<task_id>,STOP*<CHK>\r\n
$X,<x_px>*<CHK>\r\n
$X,NA*<CHK>\r\n
```
