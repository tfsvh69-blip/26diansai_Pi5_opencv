# 25 电赛 E 题视觉代码：稳定提取矩形框与激光点映射流程分析

源码参考：`源代码/视觉代码带注释.py`

这篇笔记重点不是“把每一行代码翻译一遍”，而是从开发流程角度理解这份优秀代码为什么更稳定，以及以后自己配合 AI 调试视觉项目时，应该怎样描述现象、拆问题、给证据、迭代参数。

---

## 小结

这份代码的稳定性主要来自三层工程设计：

| 层级 | 做什么 | 关键代码思想 |
| --- | --- | --- |
| 图像层 | 让矩形边框在图像里更容易被找出来 | 灰度化、反二值化、闭运算、Canny、二值区域和边缘 OR 融合 |
| 几何层 | 从大量轮廓里筛出真正像矩形的目标 | 面积、周长、四边形近似、角度检查、对边长度检查、父子嵌套、面积比过滤 |
| 坐标层 | 把识别结果变成可控制的物理误差 | 透视校正、校正图中重新找中心、面积估距、距离映射激光点、误差换算 |

最重要的结论：

**它并没有真正从图像里识别激光点。**

这版代码的激光点是根据目标距离映射出来的：

```text
识别靶纸外框
↓
用外框面积估算距离
↓
根据距离线性映射出一个激光点坐标
↓
把激光点变换到透视校正图
↓
和目标中心计算误差
```

这其实是一个很值得学习的比赛工程思路：遇到真实激光点识别不稳定，不一定要继续死磕 HSV 或亮斑检测，而是可以把问题转换成一个更可控的标定映射问题。

## 1. 这个视觉任务实际被拆成了哪些子问题

从开发角度看，它不是一个“识别矩形框”的单点任务，而是一个完整数据流：

```text
相机采集
↓
固定图像尺寸 640×480
↓
图像预处理，得到更适合找轮廓的 combined 图
↓
findContours 找所有轮廓，并保留父子层级
↓
find_rectangles 多级筛选矩形
↓
选择外框，做透视变换
↓
在校正图里重新找目标中心
↓
用外框面积估算距离
↓
用距离映射激光点坐标
↓
把激光点映射到校正图坐标系
↓
计算激光点和目标中心的毫米误差
↓
通过串口发给下位机
```

这一点对自己做项目很关键。视觉项目调试困难，很多时候不是因为某个函数不懂，而是没有把系统拆成这些层。只要不拆层，AI 也很容易被带偏，因为它只能围绕你给出的“某个算法假设”反复改。

正确思路应该是先问：

```text
现在失败发生在哪一层？
是图像层没把边框提出来？
是轮廓层找到了但筛选错了？
是矩形角点顺序错了？
是透视校正后中心错了？
还是视觉其实没问题，激光映射标定错了？
```

## 2. 图像预处理：不是为了变黑白，而是为了让轮廓更完整

主循环里的预处理大致是：

```python
frame_main = cv2.resize(frame_main, (640, 480))

blurred = cv2.GaussianBlur(
    frame_main,
    (GAUSSIAN_BLUR_SIZE, GAUSSIAN_BLUR_SIZE),
    0
)

gray = cv2.cvtColor(blurred, cv2.COLOR_BGR2GRAY)

_, binary = cv2.threshold(
    gray,
    BINARY_THRESHOLD_CORRECTED,
    255,
    cv2.THRESH_BINARY_INV
)

kernel_closing = cv2.getStructuringElement(cv2.MORPH_RECT, (4, 4))
binary_closed = cv2.morphologyEx(binary, cv2.MORPH_CLOSE, kernel_closing)

edges = cv2.Canny(gray, CANNY_LOWER, CANNY_UPPER, apertureSize=3)
combined = cv2.bitwise_or(binary_closed, edges)
```

这套流程的核心不是“灰度化加二值化”，而是：

```text
降噪
↓
把黑色边框变成白色前景
↓
修补边框断裂
↓
补充边缘信息
↓
得到更适合 findContours 的图
```

### 2.1 高斯模糊

```python
blurred = cv2.GaussianBlur(frame_main, (5, 5), 0)
```

作用是减少小噪点和纸面纹理的影响。如果不模糊，二值化后可能出现很多孤立白点，后面的 `findContours` 会找到一堆无用轮廓。

调试时的判断：

| 现象 | 可能动作 |
| --- | --- |
| 二值图里碎点很多 | 增大模糊核，例如从 5 到 7 |
| 细边缘被抹掉，矩形角不清楚 | 减小模糊核 |
| 画面本身很干净 | 不要盲目增大模糊 |

### 2.2 反二值化

```python
_, binary = cv2.threshold(gray, threshold, 255, cv2.THRESH_BINARY_INV)
```

因为目标通常是黑色边框，背景是较亮纸面，所以反二值化后：

```text
黑色边框 → 白色前景
白色背景 → 黑色背景
```

这正好符合 `findContours` 的习惯：在黑底白目标上找轮廓。

### 2.3 闭运算

```python
binary_closed = cv2.morphologyEx(binary, cv2.MORPH_CLOSE, kernel)
```

闭运算是先膨胀再腐蚀，主要用来连接断裂边缘、填补小孔洞。

在这个项目里，它尤其适合处理一种现场问题：

```text
激光打到黑边框上
↓
黑边局部变亮
↓
反二值化后那一段边框消失
↓
轮廓断裂
↓
闭运算把断裂重新连接
```

主循环里用的是 `4×4` 核，而 `preprocess_image()` 函数里用的是 `30×30` 核。这个差异说明：代码里并不是所有地方都用同一套预处理强度。

### 2.4 Canny 和 OR 融合

```python
edges = cv2.Canny(gray, CANNY_LOWER, CANNY_UPPER)
combined = cv2.bitwise_or(binary_closed, edges)
```

二值化更像是“区域信息”，Canny 更像是“边线信息”。两者 OR 起来，相当于：

```text
闭运算后的目标区域 + Canny 的精细边缘 = 更完整的轮廓输入
```

这比单独二值化更稳，因为二值化失败一点时，Canny 还能补一部分边界；Canny 有断边时，二值区域也能兜住一部分轮廓。

## 3. 代码里有一个非常值得注意的阈值命名问题

参数区定义了：

```python
BINARY_THRESHOLD = 35
BINARY_THRESHOLD_CORRECTED = 35
```

但实际主循环中，原图预处理用的是：

```python
cv2.threshold(gray, BINARY_THRESHOLD_CORRECTED, 255, cv2.THRESH_BINARY_INV)
```

而校正图中重新找中心时，会调用：

```python
combined = preprocess_image(corrected_img)
```

`preprocess_image()` 里面用的是：

```python
cv2.threshold(gray, BINARY_THRESHOLD, 255, cv2.THRESH_BINARY_INV)
```

所以这里实际效果有点反直觉：

| 参数 | 实际影响 |
| --- | --- |
| `BINARY_THRESHOLD_CORRECTED` | 主循环原图矩形识别 |
| `BINARY_THRESHOLD` | 校正图里重新找中心 |

而界面提示里写的是 `+/-` 调主阈值，`[/]` 调校正阈值。调试时如果只相信提示，可能会出现“我明明调了主阈值，为什么主画面没变化”的错觉。

这就是阅读优秀代码时必须注意的一点：

**不要只看参数名字和注释，要顺着实际调用链看它到底在哪里生效。**

## 4. 矩形识别：不是找最大轮廓，而是多级筛选

主循环找轮廓：

```python
contours, hierarchy = cv2.findContours(
    combined,
    cv2.RETR_TREE,
    cv2.CHAIN_APPROX_SIMPLE
)

selected_rects = find_rectangles(contours, hierarchy)
```

这里的关键是 `cv2.RETR_TREE`。它会保留轮廓父子关系，而不是只返回独立轮廓。

对于一个内外框靶纸，理想结构类似：

```text
外框轮廓
└── 内框轮廓
```

这比 `RETR_EXTERNAL` 更适合双矩形目标，因为 `RETR_EXTERNAL` 只关心外层轮廓，可能直接丢掉内框信息。

### 4.1 候选矩形筛选流程

`find_rectangles()` 的实际流程可以简化成：

```text
遍历所有轮廓
↓
过滤面积太小、周长太小的轮廓
↓
用 approxPolyDP 把轮廓近似成多边形
↓
只保留 4 个点的四边形
↓
检查它像不像矩形
↓
保存面积、角点、外接矩形、父轮廓编号
↓
根据父子关系找内外框
↓
父子关系不可靠时，用外接矩形包含关系兜底
↓
再不行就按面积选最小和最大矩形
↓
统一角点顺序
```

核心代码：

```python
area = cv2.contourArea(cnt)
perimeter = cv2.arcLength(cnt, True)

if area < 100 or perimeter < 20:
    continue

epsilon = 0.02 * perimeter
approx = cv2.approxPolyDP(cnt, epsilon, True)

if len(approx) == 4:
    if check_rectangle_geometry(sorted_corners):
        valid_rects.append((cnt, approx, area, x, y, w, h, i, parent))
```

这里还有一个代码和参数区不完全一致的点：

| 参数区 | 实际筛选代码 |
| --- | --- |
| `MIN_CONTOUR_AREA = 1000` | `area < 100` 直接写死 |
| `MIN_PERIMETER = 20` | `perimeter < 20` 直接写死 |
| `APPROX_EPSILON_FACTOR = 0.02` | `epsilon = 0.02 * perimeter` 直接写死 |

所以调参时，如果只修改 `MIN_CONTOUR_AREA`，矩形筛选不一定会变。这里也说明：优秀代码也可能存在“参数定义了，但主流程没用上”的问题。

### 4.2 几何检查为什么重要

`check_rectangle_geometry()` 主要检查三件事：

| 检查 | 作用 |
| --- | --- |
| 四个角接近 90 度 | 排除梯形、菱形、严重歪斜的四边形 |
| 两组对边长度接近 | 排除不规则四边形 |
| 最长边/最短边不超过 10，最短边不小于 20 | 排除细长线段、小碎片 |

这一步让程序不是“看到 4 个点就认为是矩形”，而是要求这个四边形在几何上也合理。

### 4.3 父子嵌套关系

每个候选矩形都会保存自己的父轮廓编号：

```python
parent = hierarchy[0][i][3] if hierarchy is not None else -1
```

如果某个候选矩形有父轮廓，并且父轮廓本身也通过了矩形筛选，就可以构成一组内外框候选。

但代码不会直接相信父子关系，还会用面积比过滤：

```python
area_ratio = child_area / parent_area

if area_ratio >= MIN_AREA_RATIO:
    parent_child_pairs.append((parent_rect, rect))
```

默认 `MIN_AREA_RATIO = 0.7`。意思是内框不能比外框小得太离谱。这样可以过滤掉：

| 干扰 | 为什么会被过滤 |
| --- | --- |
| 外框里的文字小轮廓 | 面积比太小 |
| 外框里的 logo | 面积比太小 |
| 反光形成的小块 | 面积比太小 |

### 4.4 几何嵌套兜底

真实图像里，`hierarchy` 不一定稳定。比如边框断裂时，OpenCV 的父子关系可能乱掉。

所以代码还有第二套判断：

```python
x1 >= x2 - margin
y1 >= y2 - margin
x1 + w1 <= x2 + w2 + margin
y1 + h1 <= y2 + h2 + margin
area1 < area2 * 0.9
```

也就是看一个矩形的外接框是否基本被另一个矩形包住。这里的 `margin = 10` 给了边界误差容忍。

这就是稳定性的来源之一：

**不是只相信一种证据，而是 hierarchy 失败后，还有几何包含关系兜底。**

## 5. 角点排序和透视校正

矩形识别出来后，下一步不是直接用原图中心，而是先做透视校正。

### 5.1 为什么必须排序角点

透视变换要求四个角点顺序一致：

```text
左上 → 右上 → 右下 → 左下
```

如果顺序错了，校正图会扭曲、交叉，后面的中心点和误差都会错。

代码里的 `sort_corners()` 大致做了：

```text
求四个点的重心
↓
计算每个点相对重心的极角
↓
按角度排序
↓
根据上下两组点的 x 坐标二次校正
```

这比简单用 `x+y`、`x-y` 排序更稳，尤其目标旋转或倾斜时更不容易乱。

### 5.2 透视校正流程

```python
M, M_inv, corrected_size = create_perspective_transform(
    outer_rect_corners.reshape(4, 2),
    target_width_mm=297,
    target_height_mm=210,
    pixels_per_mm=1.5
)

corrected_image = cv2.warpPerspective(frame_main, M, corrected_size)
```

这里把外框对应到标准 A4 平面：

```text
原图里的倾斜四边形
↓
标准 297mm × 210mm 平面
↓
每毫米 1.5 像素
```

透视校正的意义是：相机斜拍时，原图中的几何中心不一定等于靶纸平面上的真实中心；校正后再找中心，物理意义更清楚。

### 5.3 在校正图里重新找中心

代码不是直接取外框四点平均值，而是在校正图中再次调用矩形检测：

```python
center_in_corrected, inner_corners = find_center_in_corrected_image(
    corrected_image,
    corrected_size
)
```

`find_center_in_corrected_image()` 中会：

```text
对校正图预处理
↓
重新找矩形
↓
取第一个矩形，通常是内框
↓
用 cv2.moments 求中心
↓
如果失败，就退回校正图中心
```

这一步比原图直接取中心更稳，因为它把“靶纸倾斜”和“相机角度”带来的透视影响先消掉了。

## 6. 距离估算：用外框面积反推距离

距离估算函数是：

```python
distance_mm = REFERENCE_DISTANCE_MM * np.sqrt(
    REFERENCE_AREA_PIXELS / area_pixels
)
```

直观理解：

```text
目标在画面中越大 → 距离越近
目标在画面中越小 → 距离越远
```

参数：

| 参数 | 当前值 | 含义 |
| --- | ---: | --- |
| `REFERENCE_AREA_PIXELS` | 8412 | 参考距离下检测到的外框像素面积 |
| `REFERENCE_DISTANCE_MM` | 1500 | 参考距离 |
| `REAL_OBJECT_AREA_MM2` | 62370 | A4 纸面积，210×297 |

这类面积估距有一个前提：相机、焦距、目标大小、目标姿态基本固定。如果外框识别面积抖动，距离估计也会抖动。

因此调试距离时不能只看公式，还要看：

```text
外框面积是否稳定？
目标倾斜角度是否变化？
相机是否有明显畸变？
参考面积是否重新标定过？
```

## 7. 激光点映射：这个代码绕开了真实激光点识别

这一点是整份代码最值得学习的地方。

代码更新日志里写得很明确：删除激光点检测功能，改为基于距离映射的激光点坐标系统。

实际函数：

```python
def calculate_laser_position_by_distance(distance_mm):
    x = LASER_X_FIXED

    distance_clamped = max(
        MIN_DISTANCE_MM,
        min(MAX_DISTANCE_MM, distance_mm)
    )

    y = LASER_Y_MIN_DISTANCE + \
        (distance_clamped - MIN_DISTANCE_MM) * \
        (LASER_Y_MAX_DISTANCE - LASER_Y_MIN_DISTANCE) / \
        (MAX_DISTANCE_MM - MIN_DISTANCE_MM)

    return (int(x), int(y))
```

参数：

| 参数 | 当前值 | 含义 |
| --- | ---: | --- |
| `MIN_DISTANCE_MM` | 500 | 最近有效距离 |
| `MAX_DISTANCE_MM` | 1500 | 最远有效距离 |
| `LASER_X_FIXED` | 322 | 激光点 X 固定 |
| `LASER_Y_MIN_DISTANCE` | 240 | 最近距离对应 Y |
| `LASER_Y_MAX_DISTANCE` | 250 | 最远距离对应 Y |

映射关系：

| 距离 | 映射激光点 |
| ---: | ---: |
| 500 mm 或更近 | `(322, 240)` |
| 1000 mm | 约 `(322, 245)` |
| 1500 mm 或更远 | `(322, 250)` |

也就是说，这里所谓的激光点，不是摄像头看到的真实亮斑，而是根据目标距离估出来的“理论激光点”。

### 7.1 为什么这样反而稳定

真实激光点检测很容易受干扰：

| 现场问题 | 真实激光点检测的风险 |
| --- | --- |
| 激光打到黑边框 | 光斑不完整或消失 |
| 纸面反光 | 出现多个亮点 |
| 曝光过高 | 光斑饱和，中心漂移 |
| 背景有红色物体 | HSV 误检 |
| 运动中拖影 | 中心抖动 |

这份代码的思路是：

```text
既然真实激光点难识别
就不识别它
只要相机和激光器安装关系固定
就用距离映射估计它应该出现在哪里
```

这是一种很典型的比赛工程取舍：不是最通用，但在固定场地、固定机械安装、固定目标尺寸的条件下，很可能更稳。

### 7.2 这个方法的风险

它也有明显代价：

| 风险 | 影响 |
| --- | --- |
| 激光器安装松动 | 系统不知道真实激光已经偏了 |
| 相机角度变化 | 原来的映射参数失效 |
| 距离估计不准 | 激光点坐标跟着错 |
| 目标外框面积抖动 | 激光点 Y 坐标也会抖 |
| 实际关系不是线性 | 远近距离误差不一致 |

所以它不是“更高级”，而是“更适合固定比赛环境”。

## 8. 误差计算：把激光点和目标中心放到同一个坐标系

主循环里会把映射出来的激光点变换到校正图坐标系：

```python
laser_pt_corrected = transform_point_to_corrected(laser_pt, M)
```

然后和目标中心比较：

```python
dx_mm, dy_mm, distance_mm = calculate_laser_error(
    laser_pt_corrected,
    center_in_corrected,
    pixels_per_mm=1.5
)
```

误差本质是：

```python
dx_pixels = laser_pt[0] - target_center[0]
dy_pixels = laser_pt[1] - target_center[1]

dx_mm = dx_pixels / pixels_per_mm
dy_mm = dy_pixels / pixels_per_mm
```

这里的关键不是公式复杂，而是坐标系必须统一。

如果拿原图激光点直接和校正图中心比较，结果没有意义。代码先把激光点转进校正图，再算误差，这一点是正确的。

## 9. 参数调试地图

调试视觉项目时，不要一上来就问“阈值调多少”。应该先看是哪一层的问题，再动对应参数。

### 9.1 图像层参数

| 参数 | 主要影响 | 现象 | 调整方向 |
| --- | --- | --- | --- |
| 曝光 `5000` | 图像整体亮度 | 画面过暗或过曝 | 先固定曝光，再谈阈值 |
| 增益 `12` | 噪声和亮度 | 噪点多 | 降低增益或增强光照 |
| `GAUSSIAN_BLUR_SIZE` | 去噪强度 | 碎点多 | 增大 |
| `GAUSSIAN_BLUR_SIZE` | 边缘清晰度 | 角点变钝 | 减小 |
| 二值化阈值 | 黑边是否完整 | 黑边断裂 | 让黑色区域更容易变白 |
| 闭运算核 | 连接断边 | 边框断裂 | 增大核 |
| 闭运算核 | 保留细节 | 不同区域粘连 | 减小核 |
| `CANNY_LOWER` / `CANNY_UPPER` | 边缘补充 | 边缘断 | 降低 |
| `CANNY_LOWER` / `CANNY_UPPER` | 噪声边缘 | 边缘太杂 | 提高 |

调试顺序建议：

```text
先固定相机曝光、增益、白平衡
↓
再看 binary 是否能稳定提取黑边
↓
再看 closed 是否补好了断裂
↓
再看 edges 是否只是补边，不是制造大量噪声
↓
最后看 combined 是否适合找轮廓
```

### 9.2 轮廓和矩形层参数

| 参数或逻辑 | 主要影响 | 现象 | 调整方向 |
| --- | --- | --- | --- |
| 面积下限 | 去小噪声 | 候选太多 | 增大 |
| 面积下限 | 保留远距离目标 | 远距离漏检 | 减小 |
| `epsilon = 0.02 * perimeter` | 多边形近似 | 明明是矩形却不是 4 点 | 适当增大或尝试多 epsilon |
| `ANGLE_TOLERANCE` | 角度容忍 | 斜拍时漏检 | 增大 |
| `ANGLE_TOLERANCE` | 误检控制 | 背景四边形混进来 | 减小 |
| `SIDE_RATIO_TOLERANCE` | 对边长度容忍 | 透视变形漏检 | 增大 |
| `MIN_AREA_RATIO` | 内外框面积关系 | 小干扰被当内框 | 增大 |
| `MIN_AREA_RATIO` | 内框真实偏小 | 找不到内外框组合 | 减小 |

注意：当前代码里 `MIN_CONTOUR_AREA` 和 `APPROX_EPSILON_FACTOR` 定义后没有真正接入 `find_rectangles()`，要调它们必须先改实际使用处。

### 9.3 坐标和映射层参数

| 参数 | 主要影响 | 什么时候调 |
| --- | --- | --- |
| `REFERENCE_AREA_PIXELS` | 面积估距 | 换相机高度、分辨率、镜头、靶纸尺寸后 |
| `REFERENCE_DISTANCE_MM` | 标定距离 | 重新做距离标定后 |
| `LASER_X_FIXED` | 激光点横向偏移 | 激光整体左右偏 |
| `LASER_Y_MIN_DISTANCE` | 近距离激光点 Y | 近距离误差系统性偏 |
| `LASER_Y_MAX_DISTANCE` | 远距离激光点 Y | 远距离误差系统性偏 |
| `pixels_per_mm` | 像素到毫米换算 | 校正图尺寸比例变化后 |

如果误差是“某个方向一直偏”，不要先怀疑二值化。很可能是映射标定问题。

## 10. 现场调试时应该保存哪些证据

以前用 vibe coding 效果差，很可能不是 AI 不会，而是给 AI 的信息太抽象。比如只说“识别不稳定”，AI 只能猜。

更好的方式是给一个“调试证据包”。

每次失败时至少保存这些东西：

| 证据 | 作用 |
| --- | --- |
| 原图 `frame_main` | 看实际光照、目标大小、背景干扰 |
| `binary` | 判断阈值是否把黑边提出来 |
| `binary_closed` | 判断闭运算是否修复断边或过度粘连 |
| `edges` | 判断 Canny 是补边还是制造噪声 |
| `combined` | 判断给 `findContours` 的输入是否合理 |
| 轮廓可视化图 | 看找到了哪些轮廓 |
| 候选矩形可视化图 | 看哪些轮廓通过了几何筛选 |
| 最终内外框图 | 看选择策略是否选错 |
| 校正图 | 看透视变换是否扭曲 |
| 参数打印 | 复现当时状态 |
| 成功帧和失败帧各 5 到 10 张 | 让 AI 对比差异 |

最好再记录一行结构化日志：

```text
frame_id=123
threshold=35
canny=(50,150)
contours=42
valid_rects=3
selected_rects=2
outer_area=8412
distance=1500
laser=(322,250)
center_corrected=(223,157)
dx=-12.5
dy=6.0
failure=inner_rect_wrong
```

这样 AI 才能从“猜测”进入“诊断”。

## 11. 和 AI 配合调试时，如何避免被自己的思路限制

你之前遇到的问题很真实：你提出一个算法方向，AI 往往会顺着你的方向继续优化。但如果你的方向本身不对，最后就会一直在错误路径上打补丁。

所以问 AI 时，不要只问：

```text
我想用 HSV 识别激光点，怎么调参数？
```

更好的问法是：

```text
这是我的任务目标和现场约束。
我现在的方案是 HSV 识别激光点，但失败现象如下。
请先判断这个问题是否应该继续用 HSV 做。
如果不应该，请提出替代方案，并比较稳定性、标定成本和比赛现场风险。
```

### 11.1 给 AI 的问题模板

可以直接这样问：

```text
你先不要急着改代码。

任务目标：
在 25 电赛 E 题场景中，摄像头识别靶纸矩形框，得到目标中心，并给下位机发送激光点相对中心的误差。

现场约束：
相机固定，激光器固定，靶纸尺寸固定，距离大约 500 到 1500 mm，光照会变化，激光可能打到黑色边框上。

当前流程：
灰度化、反二值化、闭运算、Canny、findContours、矩形筛选、透视校正、中心计算。

失败现象：
这里写清楚，例如 binary 中边框断裂，combined 中轮廓完整但 valid_rects 为空，或者外框识别对但激光误差一直偏上。

我提供的证据：
原图、binary、edges、combined、轮廓图、最终框图、校正图、当前参数、日志。

请你做三件事：
1. 判断失败发生在哪一层。
2. 判断我当前坚持的算法方向是否合理。
3. 给出至少三种方案：参数调整、代码结构调整、替代算法或工程规避方案。
```

这个模板的关键是：要求 AI 先诊断层级，再评价你的思路，而不是直接按你的想法写代码。

### 11.2 让 AI 不被你带偏的提问方式

| 不推荐问法 | 更推荐问法 |
| --- | --- |
| “帮我调 HSV 阈值” | “真实激光点检测是否是这个场景的最稳方案？” |
| “为什么 findContours 找不到矩形？” | “从 binary、edges、combined 三张图判断，失败发生在预处理还是矩形筛选？” |
| “帮我把闭运算核调大” | “边框断裂时，闭运算、Canny、轮廓近似、Hough、minAreaRect 哪个更适合兜底？” |
| “代码不稳定，怎么改？” | “我给你 10 张成功帧和 10 张失败帧，请归纳失败类型并给调试优先级。” |
| “按我的思路优化一下” | “请指出我当前思路的风险，并给出不同路线的对比。” |

### 11.3 每次只改一个变量

和 AI 调参时，一次不要同时改很多东西。否则结果变好了也不知道是谁起作用，结果变差也不知道是谁造成的。

推荐节奏：

```text
固定相机参数
↓
只调二值化阈值
↓
记录最佳范围
↓
固定二值化阈值
↓
只调闭运算核
↓
记录最佳范围
↓
固定预处理
↓
再调矩形几何参数
↓
最后调距离和激光映射参数
```

每一步都要求 AI 输出：

```text
我改了什么
预期影响是什么
可能副作用是什么
应该看哪张调试图验证
如果失败，下一步判断是什么
```

## 12. 推荐的开发流程：一步一步搭，而不是一次写完整系统

如果从零做这个项目，建议按下面阶段推进。

### 阶段 1：离线图片验证预处理

目标：先不接串口、不接下位机，只用保存的图片跑视觉。

要完成：

```text
读取一张原图
输出 gray、binary、closed、edges、combined
把每一步保存成图片
```

通过标准：

```text
combined 图里，目标内外框基本连续
背景噪声不要比目标更明显
```

### 阶段 2：轮廓和矩形候选可视化

目标：不要直接输出最终框，先把所有候选画出来。

要完成：

```text
画出所有 contours
画出通过面积/周长筛选的轮廓
画出 approxPolyDP 得到 4 点的轮廓
画出通过几何检查的矩形
打印每个候选的面积、周长、角度、边长比、parent
```

通过标准：

```text
目标外框和内框能进入 valid_rects
明显噪声不能进入 valid_rects
```

### 阶段 3：内外框选择

目标：验证 `hierarchy` 和几何嵌套是否选对。

要完成：

```text
打印 parent_child_pairs
打印 area_ratio
画出最终 selected_rects
用不同颜色标内框和外框
```

通过标准：

```text
大多数角度下，外框被选为外框，内框被选为内框
```

### 阶段 4：透视校正

目标：只验证外框角点和排序是否正确。

要完成：

```text
把四个角点编号画在原图上
输出校正图
检查校正图是否正常矩形，不扭曲、不交叉
```

通过标准：

```text
校正图中 A4 平面方向稳定
内框位置合理
```

### 阶段 5：校正图中心检测

目标：在校正图里稳定得到目标中心。

要完成：

```text
在校正图中重新跑预处理和矩形检测
用 moments 求中心
画出中心点和目标圆
```

通过标准：

```text
中心点在静止时不明显跳动
```

### 阶段 6：距离标定

目标：先让距离估算可信。

要完成：

```text
在 500、750、1000、1250、1500 mm 处采集数据
记录外框面积
拟合或校正 REFERENCE_AREA_PIXELS
检查估算距离误差
```

通过标准：

```text
距离误差在控制系统能接受范围内
外框面积随距离变化单调稳定
```

### 阶段 7：激光映射标定

目标：确定 `LASER_X_FIXED` 和 Y 距离映射。

要完成：

```text
在不同距离下记录真实激光落点
和代码映射点比较
调整 X 固定值和 Y 端点
如果线性不够，就改成分段线性或查表
```

通过标准：

```text
不同距离下，映射点和真实激光点系统误差较小
```

### 阶段 8：接入下位机闭环

目标：视觉稳定后再让车动。

要完成：

```text
串口只发 dx、dy、distance
下位机先低速响应
记录视觉误差和实际运动结果
```

通过标准：

```text
静态误差可解释
动态误差不会无规律跳变
```

## 13. 失败现象和排查路径

| 失败现象 | 优先排查 |
| --- | --- |
| `binary` 里目标边框不明显 | 光照、曝光、二值化阈值 |
| `binary` 边框断裂 | 闭运算核、激光照射、阈值 |
| `combined` 噪声很多 | Canny 阈值、模糊、背景清理 |
| 轮廓很多但矩形为空 | `approxPolyDP`、角度容差、边长容差 |
| 外框能找到，内框找不到 | `RETR_TREE`、内框二值化、`MIN_AREA_RATIO` |
| 选到了背景矩形 | 面积过滤、几何嵌套、ROI 限制 |
| 校正图扭曲 | 角点排序、外框选错 |
| 中心点跳动 | 内框检测、moments、加多帧滤波 |
| 距离跳动 | 外框面积抖动、参考面积标定 |
| 激光误差总是固定偏 | `LASER_X_FIXED` 或 Y 映射标定 |
| 近距离准，远距离不准 | 线性映射不够，考虑分段标定 |

## 14. 这份代码可以继续改进的地方

这份代码已经很有工程价值，但不是完美的。学习时尤其要注意它的可改进点。

| 问题 | 影响 | 改进方向 |
| --- | --- | --- |
| 参数定义和实际使用不完全一致 | 调参容易误判 | 把硬编码的 `100`、`0.02` 改为全局参数 |
| 主图和校正图阈值命名容易混淆 | 现场调参迷惑 | 明确命名为 `RAW_BINARY_THRESHOLD` 和 `CORRECTED_BINARY_THRESHOLD` |
| `optimize_quadrilateral()` 定义了但没接入 | 有价值的兜底没用上 | 在 `approxPolyDP` 失败时尝试凸包和 `minAreaRect` |
| 没有多帧滤波 | 中心和距离可能抖动 | 对中心点、外框面积、距离做滑动平均或中值滤波 |
| 没有相机畸变校正 | 边缘位置会受镜头影响 | 用棋盘格标定相机，先 undistort |
| 激光点不是真实检测 | 激光器松动时无感知 | 增加可选真实激光检测作为监控，不一定参与主闭环 |
| 失败帧没有自动保存 | 现场难复盘 | 检测失败或误差突变时自动保存调试证据包 |

## 15. 我从这份代码学到的开发方法

这份优秀代码最值得学的不是某个 OpenCV API，而是它的工程思维：

```text
先把硬件和图像尺度固定
↓
把图像变成适合轮廓检测的形态
↓
不要相信单一判断，要多层过滤
↓
利用目标结构本身，比如内外框嵌套
↓
把不稳定问题转换成更可控的问题
↓
保留调试窗口和现场可调参数
↓
用可视化结果判断失败层级
```

对于以后配合 AI 开发，最关键的一句话是：

**不要让 AI 只回答你提出的算法，而要让 AI 先判断你的算法假设是否成立。**

比如这次如果一开始就说“帮我识别激光点”，AI 可能会一直围绕 HSV、红色阈值、亮斑中心做文章。但这份代码真正好的地方恰恰是：它发现真实激光点检测不稳定，于是换成了距离映射。

所以更好的 AI 协作方式是：

```text
我给你任务目标、现场约束、失败证据和当前方案。
请你先判断失败层级，再判断当前方案是否值得继续。
如果不值得，请提出替代路线。
```

这样 AI 才能从“按你的局部想法写代码”，变成“帮你一起做系统设计和工程权衡”。
